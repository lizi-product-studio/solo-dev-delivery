# 0.12.0 自主化核心重构审计

日期：2026-10-26。对象是 0.11.2 候选的入口和引用组织，目标是让 Agent 能自动识别任务、判断边界、选择验收方式并安排下一轮，同时减少重复说明和无条件流程。

## 抽象出的能力

| 能力 | 核心输入 | 可自动得出的结论 |
| --- | --- | --- |
| 任务识别 | 原始目标、产物、影响、回退难度 | `QUICK / BOUNDED / GOVERNED / MAINTENANCE` |
| 边界识别 | 授权、身份、业务政策、宿主能力、外部副作用 | `AUTO / ASK / STOP / DEFER` |
| 验收识别 | 预期结果、真实入口、持久读回、当前证据 | `DONE / NEEDS_EVIDENCE / BLOCKED / BUSINESS_DECISION` |
| 迭代识别 | 用户反馈、失败、里程碑、依赖、成本 | 下一项最小动作、停止条件、恢复条件 |

此前入口和引用多次分别描述“按风险分流”“遇阻恢复”“实际验收”“项目巡检”。0.12.0 把它们统一成 `state → route → boundary → observe → accept → next`，专用引用只负责自己的细节。

## 重复收缩

- 入口只保留总循环和三条不可混淆的约束：主 Agent 对目标负责、未知不等于成功、授权边界不能扩大。
- `delivery-self-review.md` 只保留从用户反馈生成反例和检查可见结果；恢复、交接和证据状态回到核心循环。
- 正式门禁、隔离反例、宿主接入、本机队列和前端质量继续保留，因为它们有不同工具、风险或领域事实；入口通过路由按需读取，不默认全量加载。
- 没有把某个客服案例写成全局业务规则，也没有新增固定重试次数、全量测试数量、强制计划、工作树或子 Agent。

## 预期行为

简单小改仍直接完成和读回；复杂度、风险或不确定性上升时才提升方法深度。技术阻塞先自行恢复，业务/身份/高风险未知才最小交接。完成一个局部步骤后继续原目标；只有真实结果与当前证据满足停止条件才结束。用户反馈会成为下一轮候选信号，经过去重、影响和成本判断后才进入迭代计划。

## 待验证指标

下一轮真实任务记录：可恢复阻塞首次交接率、用户实际决策交接准确率、用户首次纠正次数、异常反例漏检数、旧状态误执行率、未知结果被报告为成功的次数、迭代后返工和总资源消耗。没有同口径基线时保留未知，不用 Skill 自评或规则文字长度证明收益。
