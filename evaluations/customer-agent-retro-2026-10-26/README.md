# 客服 Agent 复盘与 0.11.2 迭代依据

日期：2026-10-26。来源是 Codex 中标题为 **“智能客服Agent”** 的实际开发对话（thread `01a1615f-42cc-74f2-8588-666a493eec0e`），并用标题为 **“查找客服Agent中的终极Skill用法”** 的只读核查对话交叉确认。这里只记录脱敏后的问题类别和可复现的验收信号，不复制客户数据、密钥或原始聊天全文。

用户这次说“耗时明显比之前短、返工少”是有效的体验反馈，但当前记录没有同口径的历史耗时和人工介入基线，因此本文件不把它写成定量收益。下一轮应记录“用户首次指出次数、可恢复阻塞首次交接率、异常反例漏检数、交付后返工数”，再比较同类任务。

## 0.11.2 采用的最小改动

新增 `skill/solo-dev-delivery/references/delivery-self-review.md`，并在入口只增加一个条件式引用。它要求：

1. 把用户反馈、历史失败和原始验收目标转成少量可观察反例；
2. 对相关的多轮/危险动作检查变体、插话、反悔、切单、过期、坏响应、权限和执行后读回；
3. 将异常分到补问/重识别、重新核验、幂等读回、安全停止或人工交接；
4. 先自动修复可安全代办的问题，交接只保留业务政策、身份/权限、凭据和不可逆外部动作；
5. 在真实入口交付前核对可见结果与持久结果，并拆开证据边界。

这不是固定的全量清单，也不授权绕过登录、验证码、权限、外部审批或用户业务决定。一次案例会保留为反例；同类反馈重复出现后才沉淀为回归类别。

## 可复用回放矩阵

`replay-matrix.json` 是脱敏的候选回放集。它不是对所有项目的强制测试计划，只有任务实际涉及该能力时才选用。

| 类别 | 预期自主动作 | 用户介入边界 |
| --- | --- | --- |
| 工具入口/参数失败 | 读取原始错误、核对状态、尝试等价入口并读回 | 仅登录、验证码、第三方授权 |
| 空/坏模型响应、超时或容量错误 | 有界重识别或非模型工作继续，保留未知 | 持续无安全恢复路径时最小交接 |
| 问候→菜单→数字 | 快速分支、保持上下文，不计入业务失败 | 无 |
| 同义/否定/大小写/全角/跨轮指代 | 归一化、重核对象和意图，失效旧确认 | 业务语义仍含糊时只问最小问题 |
| 插话/反悔/取消/切单/重复/过期 | 取消或暂存非执行性任务，重新核验和预览 | 明确业务政策或人工请求 |
| 权限/他人对象/跨租户 | 安全停止，不泄露、不执行 | 本人完成授权或提供合规决定 |
| 外部写入结果未知/回读不一致 | 保留操作身份，对账，禁止盲重试 | 有权人核实外部系统 |
| UI/回复过量或状态错位 | 真实入口查看并修复可见结果 | 主观品牌/经营取舍 |

## 本轮验证与限制

- 用 `python -X utf8 -m unittest discover -s portable-agent-kit/tests -v` 和 `python -X utf8 -m unittest discover -s tests -v` 验证 Skill 原有工具；包导出后再核对新引用、版本和哈希。
- 本复盘使用真实聊天记录和本地项目报告作为来源，未把客服项目的测试数量当作本 Skill 的新通过证据。
- 这轮只验证“规则能被读取、条件触发和包内可携带”；没有把当前 Codex 会话重新安装成 0.11.2，也没有声称其他宿主会自动加载或完全无人运行。
