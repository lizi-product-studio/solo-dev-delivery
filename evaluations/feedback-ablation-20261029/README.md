# 轻量模型验收反馈对照：未证明总体收益

模型请求为 `gpt-6-luna`、effort 为 medium、每笔最多 16 个决策步骤。两组都使用 AGI-like Runtime；baseline 仅执行合同门禁，feedback 在任务中额外接收宿主 unittest 失败反馈。两组结束后运行同一判分器。这是验收反馈机制的对照，不是裸模型与完整 AGI-like 的对照，也不是不同框架排名。

各轮修改了运行协议，必须分别报告，不能合并成功率。每轮每题只有一个配对，无统计显著性或跨行业泛化结论。完整原始目录及 summary/protocol 哈希见 [RESULTS.json](RESULTS.json)。

| 协议轮次 | 任务 | baseline 通过 | feedback 通过 | 观察 |
| --- | --- | --- | --- | --- |
| r1 | 软件、数据、采购 | 1/3 | 0/3 | 出现原生宿主工具偏离及 JSON 协议错误 |
| r2 | 软件、数据、采购 | 2/3 | 2/3 | 加入严格输出 schema、纯决策指令及配置隔离；采购仍失败 |
| r3 | 软件、数据、采购 | 2/3 | 2/3 | 加入 JSON 工具；业务文档 status 被误作工具状态，采购被阻断 |
| r4 | 仅采购 | 0/1 | 0/1 | 修复 status 包装；baseline 多出字段，feedback 预算耗尽且 JSON 与文本不一致 |

成功同时要求 Runtime 完成、最终独立执行的测试通过、输入已读取、源文件与判分器未变化。r4 baseline 的合同门显示 COMPLETED，但完整最终业务测试失败，因此仍计失败。feedback 的拒绝不代表系统把任务做完。没有把失败、未知或达到预算上限的任务改判成功。

原始 usage.model_calls 统计的是 CLI 决策进程次数，不是底层推理请求次数；完整费用未知。验收反馈与最终判分使用同一套测试，不能称为未见过的隐藏评测。数据合同中的精确数值也限制了题目难度。

实验结束后的源码修复纳入 1.3.0 候选，原始回执保持不变：

- read_json 用 data 包装业务对象，防止业务 status 污染执行状态；write_json 直接序列化结构化值。
- 正常回答、模型工具越界、JSON 协议错误不再因包含 network/forbidden 等字样被剔出失败分母；不明确的环境错误保留为观测失败。
- API provider 不支持 effort 时明确拒绝，避免记录了配置却没有发送给模型。
- 决策子进程出现未受管宿主动作、超时或不完整事件时，保持 UNKNOWN/ACTION_PENDING，续接前需要绑定动作的可信读回，不自动再次调用模型。该修复使用本地子进程替身测试副作用与防重复，未重新执行这些真实模型对照。

关闭 shell、App 和插件功能可减少暴露面，但当前 Codex CLI 路径没有经过“全部 MCP 工具事前不可用”的证明。事后 UNKNOWN 停止不能撤销已经发生的外部副作用，也不能替代宿主权限隔离。当前桌面聊天自动接管、长期无人值守运行、真实业务系统适配及稳定增强轻量模型仍未完成。

本机制实验阶段较早启动的全量测试为 523 passed、1 skipped、186 个子测试通过。随后宿主 UNKNOWN、error-only 非终态、API 参数拒绝及统计修复经过相关 40 项、30 个子测试通过。更晚的 1.3.0 目标入口和宿主主动验收记录见[后续验收](../goal-runtime-20261029/README.md)，不回改本实验结论。
