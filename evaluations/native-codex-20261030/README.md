# Codex日常会话接入与真实交付（2026-10-30）

本次改动解决日常加载Skill却没有进入Runtime的问题：由本地stdio MCP公开native_start/status/verify，当前Codex保留模型、原生工具和上下文；原生hooks提供真实用户请求、调用观察与结束验收，失败自动返回同一会话修复。没有为普通任务额外启动JSON决策模型。

## 实际观察

普通代码任务使用已安装的用户Skill、本地MCP和已信任的用户hooks，workspace-write沙箱下没有启用hook信任绕过。gpt-6-luna修复报价函数，9项独立内容/行为检查通过；Native与控制面均COMPLETED，待对账动作0。只观察到1条初始用户消息，无追加人工纠正。登记后的4个原生工具调用不是全任务模型请求数或费用。输入和验收脚本哈希保持不变。

开发期还做过明确标注的故障注入：先写41，真实Stop验收失败，继续同一会话改42后通过。它证明返修机制，不能当作自然业务成功率提升。最终源码中的失败反馈、返修上限、无效完成失效、异步/中断未知、原目标绑定、下一任务不继承PASS、项目测试冻结、MCP协议及路径归一化均有定向回归。

## 失败如何处理

RESULTS.json逐笔保留各轮观察及原始记录哈希。状态目录权限、脚本发现、验收命令等待自身、MCP未配置调用许可、绝对路径格式，以及前置意图被误当成仍在运行，均曾阻断接入，未改判成功。最终适配器把意图、观察缺口、明确异步运行和中断未知分开；正常Stop只对本地候选做独立验收，不认证所有工具轨迹/外部副作用。未配对意图保留为partial覆盖，不据此重放动作。

本机原始记录在 outputs/native-codex-20261030-r1 至 r9；最终不可变回执在 ~/.agi-like/native/tasks/native-2f2dd361a0cb468a/receipts/。只发布合成任务、候选、可信验收与摘要，不发布用户配置、身份材料、原始聊天或完整本机日志。

## 使用边界

本机已注册MCP服务，例行许可只开放三个本地Runtime工具；其余Codex/MCP批准策略保持。原生hook的PreToolUse、Stop在Codex /hooks中核验为Trusted，真实任务中有接收事件的证据。已安装文件仍不代表所有当前聊天都热加载了新增工具；在新会话中使用agi-like，由Agent实际接入并返回回执。

这是本地软件交付样例，不是客户生产、跨行业收益或统计显著对照。缺可信检查时仍需Agent先准备或复用验收；普通模型在任意任务上持续变强尚未证明。外部业务动作、真实异步进程和中断未知仍需对应适配器，不自动重试。
