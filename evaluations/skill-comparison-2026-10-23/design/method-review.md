# 比较方法独立审查（2026-10-23）

建议把 3 题 × 3 组 × 2 次的 18 run 定义为**受控探索试验**。它能展示具体任务的结果与成本差异，不能证明普遍优胜或统计显著性。审查只读现有评测、运行本机 CLI 帮助并查官方文档；未运行候选模型任务、未读取密钥、未修改主仓库。

## 正式运行前必须冻结

- 冻结任务公开文件、独立判分器、隐藏输入、随机顺序、每 run 上限、交接处理与无效运行标准，保存哈希。出题/审查在看结果前完成；不得按某组失败即时改题或只重跑落后组。
- 三组模型名称、实际解析模型、推理强度、CLI 版本、权限、网络、MCP、子 Agent 能力、环境变量白名单、超时与工具完全相同。只有 Skill 安装不同。不要为 Superpowers 禁委派、禁正常工作树、限读引用，或保留 Solo 专属 hooks/全局恢复指令。完整安装与纯 SKILL.md 是不同处理，应按上游原生 Codex 集成固定方式。
- Solo 固定 0.11.0 包及文件哈希；upstream Superpowers 固定远端 URL、commit、安装文件哈希与集成步骤，不能只记录会移动的 main/latest。无 Skill 组允许宿主不可移除的内置基础能力，但需准确命名为“无额外工作流 Skill”。
- 统一中性业务提示，不把本聊天的 AGENTS、记忆、用户偏好、Solo 工作流、评测答案或组间反馈附给执行者。每 run 是新进程、新会话、新项目副本、新服务状态；不能 fork/resume 作者或上一 run 的上下文。

## 隔离与防污染

1. fresh CODEX_HOME 不是充分条件。官方技能文档还列出 `$HOME/.agents/skills`、repo 各级 `.agents/skills`、admin/system 路径；AGENTS 从 CODEX_HOME 及项目根到 CWD 拼接。临时任务应有独立 Git 根，枚举真实指导来源与所有可发现 Skill。不要只凭“模型说没有看见”证明隔离。
2. 本机 `codex exec --help` 支持 `--ignore-user-config`、`--ignore-rules`、`--ephemeral`、`--json`。其中 ignore-user-config 明确只忽略 config.toml；ephemeral 只不持久会话。它们不能单独证明 AGENTS/skills/memory 均未加载。配置里的 `[[skills.config]] enabled=false` 与 ignore-user-config 的组合尤其要实测，不能假定禁用项被读取。
3. 用单独、可销毁的校准会话检查加载来源、能力清单和运行日志；校准提示不进入正式任务。三种配置均应有校准证据。正式 run 不先询问 Solo/Superpowers 定义，以免校准本身改变行为。
4. 任务作者若继承父对话，仍可能看到 Solo 全局偏好；“没有主动读候选 SKILL.md”不等于完全盲。报告出题上下文来源，并由不看组名与结果的审查检查任务中是否写入恢复步骤、指定流程或 Solo 术语。
5. 隐藏 oracle、判分器、其他组产物和旧试题放在任务树外，不向模型提供路径。全盘权限下这仍是受信的范围约定，不能宣称 OS 防泄漏。保留命令/文件读取审计；缺少审计只能记未知，不能据最终文件断言未越界。

## 判分与交接

- 主要质量得分来自真实代码入口、独立输入、正式产物和服务账本；不按计划数量、TDD 字样、文档、委派、Skill/gate 文件或最终自评加分。完整业务契约应决定权重，单个可绕过的固定样例不够。
- 正确的必要权限/身份交接是边界正确，不是失败；缺少可独立完成的部分另算未完成。首轮不必要停顿记为交互成本及首轮未完成，不能直接扩大为“最终无法完成”。同时保留“首轮自主交付率”和“预注册交互协议后的完成率”。
- 若做后续交互，预先定义各类问题的同一事实答复及最大轮数，不给定向调试提示；所有组计同等交互成本。没有预注册协议就只报告首轮状态，避免事后挑选继续某组。首次完成、必要交接、不必要交接、预算耗尽、宿主故障应分列。
- 外部响应丢失题按服务唯一业务操作核重复副作用，允许任一合法等权限恢复路径；不要要求先撞默认失败入口，也不要求固定重试次数。服务故障注入要按操作条件确定，不能被组顺序、启动时钟或前次状态改变。
- 判分器先做空白必败、参考解必过、典型错误必败的自检。只检查公开的输出 schema；语义相同的合理格式不应被秘密枚举判失败。
- 保留所有启动与失败。宿主/API 故障先标 infra_error，不混为 Skill 失败；模型耗尽预算、错误命令或重复副作用属于任务表现。无效与补跑规则须组间一致，原记录不删除。任何 checker 修订保存旧版、新版、原因与全部组重判，不能把修订通过写成首次通过。

## 成本与结论

- 每 run 保存命令参数（去密）、启动/结束 UTC、退出原因、JSONL、stderr、最终回复、代码 diff、独立验收结果、服务动作日志和配置清单。`turn.completed` 等用量事件先用校准 run 核实际 schema，再统计；不能以 stdout 字符数估算 token。
- 分列 input、cached input、uncached input、output、reasoning（若存在）、响应/工具调用、失败次数、用户交互与墙钟时长。cached input 属于 input，reasoning 通常属于 output，不重复相加。父子 Agent 以实际响应身份去重并完整纳入；无法观测的子用量标缺失，不能填 0。
- Skill 正常读取、引用展开、委派、失败恢复都纳入执行成本；出题、安装与评测协调另列一次性成本，不暗中摊给某组。订阅用量不直接换算金额或额度百分比。缓存命中会随顺序变化，报告缓存差异，不能只报总输入便宣称省钱。
- 按任务与重复逐项展示原始结果，再给组汇总；不要只报通过者平均成本（会排除昂贵失败）。对不完整 run 同时报已花资源及终止原因。18 run 中每组只有 6 次、每题仅 2 次，任何胜率或成本差异均应称本轮观察，不作普遍优胜结论。
