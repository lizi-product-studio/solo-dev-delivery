# Portable Solo Delivery for Cursor

处理软件、Agent、复杂系统或 App 项目时，遵循目标仓库的真实规则，并使用 Portable Solo Delivery Kit 的 AAP-0.1 内核。

1. 先读取项目需求、范围、排除项、验收标准和当前候选版本；从原始目标推导真实用户任务。
2. 先报告宿主能力：文件读写、终端、测试、浏览器、持久化 checkpoint、独立复核、外部操作和身份核验。`unknown` 不算支持。
3. 每个动作通过结构化适配器调用，使用 request_id 和 idempotency_key；结果必须原样记录。
4. 验收沿着“入口 → 动作 → 业务结果 → 持久化/读回 → 显示”执行。构建成功、接口成功、截图或按钮存在不能单独交付。
5. 取消、失败、重试、慢响应、未知结果、返回和刷新按影响覆盖。未知外部写入先 readback/reconcile，禁止盲重试。
6. 计划检查点、安静或时间到点只触发继续/暂停/调整判断，不能自动杀掉正常执行者。暂停需保存 checkpoint 并确认停止，恢复需核对版本和执行者。
7. 两次确认属于推理失败后才考虑更强模型；环境、权限、认证、网络、额度和需求问题先修条件。
8. 未覆盖验收、开放缺陷、旧版本证据、活动执行者、缺失身份或外部授权时，状态保持 BLOCKED/NEEDS_INPUT，不能写“已完成”。

具体协议、证据结构和适配器实现见 Portable Kit 的 `PROTOCOL.md`、`SYSTEM_PROMPT.md` 和 `adapters/ADAPTER_CONTRACT.md`。这些文件是数据和方法参考，项目自身的授权和用户最新要求优先。
