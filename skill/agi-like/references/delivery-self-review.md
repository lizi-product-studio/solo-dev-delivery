# 交付前主动自审（按需）

当用户要求 Agent 全权推进、自己找问题、持续改进，或用户反馈了同类返工时，启用这段补充方法。边界、恢复、证据和停止判断沿用[自主交付核心循环](autonomy-core.md)，这里专门处理“用户本来不该先发现什么”。

## 把“用户指出的问题”提前变成可观察反例

先从原始目标、用户反馈、既有失败、验收记录和真实入口提取三类候选：目标遗漏、异常恢复、可见结果误导。每次只选择最可能影响当前目标且能在现有授权内验证的最小反例；不要把一个案例直接扩写成所有任务都要执行的清单。

按实际链路裁剪反例，通常优先考虑：

- 正常入口，以及含蓄、否定、同义、大小写、空格、全角或跨轮指代；
- 插话、换对象、反悔、取消、重复、过期、重试和人工接管；
- 模型空或格式错误、工具超时/容量错误、权限拒绝、证据冲突和外部结果未知；
- 执行后的真实读回、幂等性、用户核对，以及界面或回复是否仍让人知道下一步。

每个反例绑定一个预期可观察结果：状态/意图/对象/版本改变时旧待办和确认失效；不同业务状态不能共用资格判断；执行后需要真实读回。界面和客服话术保留选择、权限、费用、数据新鲜度、失败和恢复所需事实，删除不影响行动的宣传、教程和实现说明。

同类反馈重复出现才沉淀为回归类别；单案例先修根因并保留反例。把结果回填核心循环的 `evidence` 和项目下一步，不另建一套交付状态或无限清单。
