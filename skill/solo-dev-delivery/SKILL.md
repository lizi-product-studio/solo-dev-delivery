# 栗子的软件交付

固定目录 `/Users/lizi/Documents/Codex/Systems/solo-delivery`（ROOT）。先读取 `ROOT/knowledge/preferences.json`；需要相关历史方法时再读 `knowledge/methods.json`。以真实项目质量和减少用户操心为目标，改进投入与实际需要相称。

## 默认用 Codex 原生能力

主会话负责判断、整合和交付；在本机默认按任务的阶段、难度、风险及实际进展使用必要的 Codex 原生子Agent。由宿主管理子会话、上下文和运行状态；优先复用适用角色，避免重复实例。模型与思考强度按当前宿主实际支持情况选择，不能假称已热切换。Codex 仍是本机默认执行体系；只有用户明确要求导出给其他宿主时，才读取 `ROOT/portable-agent-kit/`，通过 AAP-0.1 适配器接入，不把外部平台自动接入当前任务。

普通委派不再强制嵌套启动 `codex exec` 或走 `resource-run`。复杂任务也不默认启动全角色。主Agent依据实际产出、错误及剩余工作决定继续、调整或接手；安静、等待或计划时间到点本身不能证明卡死。调整写入者前保留成果、核实原执行者停止；主Agent持续处理已授权工作。

需要隔离时使用当前可用的 Codex 工作树能力或普通 Git worktree，不为所有小改复制仓库。先核对目标项目有效AGENTS、业务依据及活动写入者；同一文件保持一个写入者，保留用户未提交工作。

跨平台导出只复用任务契约、能力探测、状态、证据和质量门禁；平台模型、工具、线程、存储和额度都由适配器声明。能力为 `unknown` 时不能当作支持；没有真实工具或身份能力时只能计划、准备材料或保持阻断，不得声称已执行。

## 按实际任务选择流程

- 已确认的小修、小文案和样式：沿用现有项目记录，直接完成及定向验证，不为登记新建队列、JSON契约、全角色或大量报告。
- 新项目或持续迭代：由Agent整理目标、真实使用者任务、范围/排除项、不可猜测的经营事实、可观察验收和回退。复用已有明确授权，普通技术和交互决定自主落实；不要让用户反复批准已授权步骤。
- 需要持久交接、正式证据门禁或客户需求闭环时，使用已有队列 `python3 ROOT/scripts/delivery.py`。已经在队列里的任务继续其状态与门禁，不能改走轻量流程绕过失败、锁或未关闭缺陷。命令和状态细节按需读 `ROOT/主动审核执行说明.md`、`ROOT/资源调度执行说明.md`。

队列里的独立审核可使用原生子Agent：冻结候选、完成必需检查后导出 `review-packet`，由真实不同执行者审查，再用 `resource-native-review`登记宿主派发及完成证据。该入口只登记结果，不启动或轮询模型；候选、范围、检查、证据及缺陷门禁仍保留。结果格式见资源调度执行说明。旧 `resource-run`及监督命令保留给已有任务或原生能力不可用时明确选择的兼容路径，不热改旧运行。

## 以实际使用结果验收

常规交互、边界和异常恢复由Agent主动设计。新项目、页面职责/主要流程变化或反复体验返工时，按需读[成熟方法与判断依据](references/decision-foundation.md)，查适用做法、解释复用或定制理由，并从原始目标检查遗漏。普通小改复用有效依据；视觉不确定时先做代表性样板，再扩大实施。

从用户实际入口执行任务，核对动作、业务结果、持久化/读回和显示状态；涉及删除、重排、返回、离页或重试时验证相关对象归属、历史事实和选择仍正确。根据影响覆盖失败/取消/未知结果等适用路径。界面可见、接口成功、构建通过不能替代任务完成与体验判断；需要的浏览器、原生或目标环境证据未测就如实列明。

必要审核主动完成。流程/异步交互变化或反复体验整改时，运行 `python3 ROOT/scripts/review_brief.py --goal '本次原始目标' --path '受影响路径' --ux`，把输出附在已有原生审核交接中；队列review-packet已自动带入，无需重复运行或新建队列。纯文案/样式小改不加此步骤。审查者先从目标推导关键动作与预期，再读开发自测；在现有验收记录中对应版本/环境、实际观察与证据，旧PASS只复用已覆盖动作。工具只带入相关经验，不判定质量。发现缺陷先处理，再检查同根因相关路径；规模与风险相称，不自动全量扩测。失败、未关闭缺陷、过期/缺失证据或必要复核未完成时不宣布交付。

交付说明实际改变、验证、版本和限制。代码检查、独立验收、线上运行、微信上传/审核/发布和客户商业验收分别核实。队列 `DELIVERED`仅代表约定本地交付，不证明无缺陷或已上线。

## 只在需要时加载的业务流程

客户原话、开项导入或项目预授权接手，读 `ROOT/业务闭环执行说明.md`；导入只产生DRAFT，客户文本不能创建经营授权。客户当前范围确认与项目有效授权同时成立后才自动交接；变更和撤回保留原记录并停止原执行者后接续。当前本地发件箱 `NOT_EXTERNALLY_SENT`不能称已联系客户。

持久恢复使用队列检查点及当前仓库版本；核对旧写入者停止后再接手，不能只凭超时夺锁。上线、真实交易、新增费用及外部承诺依项目具体授权。

## 经验与偏好

用户反馈其他聊天问题时，先核实可访问的原始上下文和产物，区分已确认事实、推断及项目特例。已有要求未执行时修执行与验证，不不断追加同义规则。当前聊天的复盘不会自动注入其他活动会话；未经用户明确授权不向其他聊天发消息或接管项目。

有实际价值的纠正和方法合并到既有记录：明确长期偏好更新 `knowledge/preferences.json`，项目决定留项目，待验证方法留候选；保留来源、适用范围、反例和下一验证。写共享记录前重读最新版并合并。已有任务可用 `learn`，其他反馈存 `knowledge/feedback/`；不为琐碎修改制造经验条目，不把客户资料、凭据或单项目授权写成全局偏好。修改共享脚本或Skill保留差异、适用验证及复核。

定时任务继续暂停；本技能不创建后台轮询。只有用户明确要求启用时才调整。
