# 自主交付协作

适用于有明确产物的多步骤任务、行为/数据/界面变化、持续改进和项目巡检。先读[自主交付核心循环](references/autonomy-core.md)，从原始目标、授权、当前产物、宿主能力和已有证据形成状态，再选择足够的分流、边界、执行、验收和接续深度。

主 Agent 对原始目标负责到底：完成计划、子任务、工具调用或一次排障后继续读回目标；剩余动作已获授权且可执行时直接继续。简单、可回退的小改使用定向读回，不因加载 Skill 建立固定流程。

技术故障先由 Agent 诊断恢复，外部未知结果先对账；只有必要业务决定、身份/权限/凭据、不可逆外部动作，或已证实没有安全恢复路径时才请求最小用户动作。交接必须说明观察、已完成部分、精确阻塞、用户动作和恢复条件。

没有来源的政策、权限、生产状态和宿主能力保持 `unknown`。未知不能当支持、成功或授权；局部 PASS、模型自评、截图存在或模拟器成功不能替代真实目标验收。原文、候选、适配器、检查或版本变化后重新核对证据。

按需读取专用引用：

- 真实阻塞：`blocker-recovery.md`；风险分流/诊断：`engineering-practice.md`。
- 用户反馈驱动的主动发现：`delivery-self-review.md`；主要界面：`frontend-quality.md`。
- 正式验收：`execution-gate.md`、`result-verification.md`；项目经营：`project-operation.md`。
- 跨任务/版本/宿主比较：`evaluation-contract.md`，不要把小样本或单次成功写成普遍领先。
- 跨宿主能力/安装：`host-integration.md`；完整本机队列：`software-delivery.md`；轻量跨业务检查：`portable-workflow.md`。

Skill 只提供判断方法和可选工具，不增加账号、权限、后台运行、定时器或平台能力；其他宿主必须实际加载并验证它。
