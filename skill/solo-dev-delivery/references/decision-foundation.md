# 成熟方法的检索、适配与独立检验

目标：在新项目、明显改变产品职责/工作方式的迭代、反复体验返工中，先形成有依据的方案，再扩大实施。不能把填完表格当成产品判断过关。局部文案/样式/明确修复复用有效依据，不重复研究。

## 通用方法与领域知识分开

通用层负责：明确结果、查找成熟方法、解释适用条件、比较选择、做小范围验证、记录失败和修正。领域层负责电商的商品订单、营销的归因实验、机器人作业的物理与安全约束等。领域陌生时显式标记知识缺口，先研究/实验；不能因通用流程通过就宣称具备行业能力。按已授权任务采用本领域规则与实际工具；不会因复用方法自动获得交易、外部通信或硬件操作权限。

## 从目标建立外部基线

1. 从原始需求独立列出真实使用者任务、成功结果、规模和环境。目标、使用入口、前置条件分别表达。例如查订单是用户任务，登录通常是访问私人订单的前置条件；展示登录提示本身并非错误，关键是入口职责、登录后返回目标与状态清楚。
2. 查当前项目已有且有效的模式，再查适用的官方产品说明、平台规范或真实可观察的成熟做法。记录来源、实际观察、适用原因和不适用之处。链接/产品名不能充当看过和验证过的证据。官方功能文档只能支撑功能与信息架构，不能冒充实操或审美验证。无需为每个小改重新联网或凑固定参考数量。
3. 对实际影响的选择分别决定复用、调整或定制。偏离成熟惯例需要用户任务或业务差异的依据，以及可观察验证；品牌、体量或流行度本身不足以证明适用。真正创新也保留成熟的基础操作。没有适用参考时记录查找范围，设计最小实验，不能伪造参考。
4. 明确本次省略的经营任务及原因：已有替代路径、已有覆盖、不适用、范围外或尚缺信息。空白清单不能证明完整；不能以完整性为由擅自扩建。

## 软件领域的例子，不是跨领域强制模板

电商后台可从经营对象与日常任务建立导航，常见对象为商品、订单/售后、客户和设置。校服里的学校、班级、集中发放属于需单独评估的差异。避免按代码表、接口名称或实现方便程度拼菜单。新建/编辑、列表筛选、批量操作及返回列表须贯穿实际工作。

移动端按主要目的地组织入口。首页、订单、个人服务是校服购物可评估的基线；底部导航和固定三个标签不是所有应用的必选项。订单可以放在“我的”下，但应有明确可发现的路径。登录过期不能让“订单”永久退化成登录页，登录后应回到原目标。

对视觉方向和交互结构尚不确定的任务，先做代表性页面/旅程，以实际内容、目标视口和可操作状态验证。不要批量生成所有页面后才问是否满意。已确认样板持续复用，不能把样板确认变成每次都找老板拍板。

## 主 Agent 的放行责任

主 Agent 对照原始目标、有效决定和成熟参考检查产品方案，不能只看产品 Agent 的结论。独立审查者先自行推导使用者任务，再与方案比较，特别查“完全没做”的任务、前置条件与目的地混淆、偏离惯例的依据，以及实际操作与承诺是否一致。审核者不继承实现聊天中的自我评价。

技术测试、任务完成、体验/视觉判断分别给结论；证据不覆盖时明确未验证。主观质量不能由JSON校验器或模型互相说PASS认证。参考适配的效果要靠实际操作和后续用户结果验证。

## 当前使用方式与执行候选状态

方法已接入技能入口。主Agent在上述适用任务中记录原始目标、用户任务、成熟参考及适用限制、复用/调整/定制理由和可观察验收，再按现有流程实施及独立检验。常规小改复用有效依据。

2026-10-16的程序门禁升级尚未启用。候选实现、模板及验证记录保存在ROOT/evidence/decision-foundation/；完整运行工作区仅保存在原机，导出包不包含这些历史证据。候选有结构、证据哈希、旧结论失效及上下文传递能力，但最终独立复核未通过，本任务资源预算已触发停止。不能宣称当前固定系统已自动强制decision_basis，也不能用候选测试通过代替交付。

## 方法的验证与淘汰

校服失败案例是训练/回归案例，不是泛化能力证明。另用未向执行者透露预期答案的跨情境任务作前向验证，保留原始回答与未通过项。指标包括首次发现遗漏、同类问题复发、用户重复纠正、实际任务完成及成本。单次模拟通过只证明该样例表现；只有在后续真实工作中复现有效才升级方法可信度。无效或造成机械套用的方法合并、收缩或淘汰，不不断添加同义规则。
