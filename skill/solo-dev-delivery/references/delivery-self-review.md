# 交付前主动自审（按需）

当用户要求 Agent 全权推进、自己找问题、持续改进，或任务会改变多轮行为、权限、外部结果、生产接入或主要界面时，启用这段方法。普通问答和明确、可回退的小改继续轻量处理，不因加载 Skill 建立固定流程。

## 把“用户指出的问题”提前变成可观察反例

先从原始目标、用户反馈、既有失败、验收记录和真实入口提取三类候选：目标遗漏、异常恢复、可见结果误导。每次只选择最可能影响当前目标且能在现有授权内验证的最小反例；不要把一个案例直接扩写成所有任务都要执行的清单。

对多轮或有副作用的动作，按实际链路裁剪检查范围。通常优先考虑：

- 正常入口，以及含蓄、否定、同义、大小写、空格、全角或跨轮指代；
- 插话、换对象、反悔、取消、重复、过期、重试和人工接管；
- 模型空或格式错误、工具超时/容量错误、权限拒绝、证据冲突和外部结果未知；
- 执行后的真实读回、幂等性、用户核对，以及界面或回复是否仍让人知道下一步。

每个检查都绑定一个预期的可观察结果。状态改变、意图改变、对象切换、预览过期或结果不可信时，旧待办、目标和确认必须失效；恢复需要重新识别、核验或预览。不同业务状态的资格条件不能因为名称相近而共用一个判断。对界面和客服话术，保留会影响选择、权限、费用、数据新鲜度、失败处理或恢复的事实，删除不影响行动的宣传、教程和实现说明。

## 先恢复或继续，再决定是否交接

把失败归入当前最小动作：补问/重识别、重新核验、幂等读回、安全停止或人工交接。在业务政策没有要求立即人工的前提下，一次信息缺失、一次格式错误、普通问候或菜单输错默认不直接锁人工；明确权限或业务不允许、持续失败、结果不确定、用户明确要求人工时才交接。交接记录触发事实、已完成部分和最小恢复条件；受阻期间继续完成不依赖该障碍的工作。

技术错误先核原始错误、输入、上下文和已有结果，尝试有依据且可回退的修复或等价入口，重走原动作并读回目标结果。外部写入结果未知时按原操作身份对账，不盲目重复。不能安全代办的身份、权限、凭据、业务政策和不可逆外部动作仍需用户或有权人决定。

## 交付时说明证据边界

把结论拆成：已在真实入口验证、仅本地/模拟验证、需要外部授权或真实环境、未知。工作流、受控 Agent 和自主决策循环按实际实现分别描述，不能用“真正 Agent”“生产级”或一组局部测试替代能力边界。自审降低用户发现缺陷的概率，但不证明逻辑永远正确，也不能替代用户对业务政策、身份授权和上线承诺的确认。

同类反馈出现多次时，沉淀为可复用的回归类别；只出现一次时先修根因并保留反例，不把单案例变成所有任务的硬规则。
