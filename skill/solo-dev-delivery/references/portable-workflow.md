# 跨业务工作与本地检查

先确定原始目标和专业标准，默认直接使用宿主工具完成工作。独立包只携带一次性反例与关系检查，不携带持久session、旧状态机或契约示例；不要为保存自检结果重建这些组件。

## 一次只解决当前不确定性

给执行者当前子目标、原始输入、必须保留的事实、产物路径和可观察结果；读回实际产物后再决定下一步。必要的独立审查交给不同上下文。没有子Agent时可串行检查，但不能自称独立。

状态变化或多来源结果，按[反例重放与关系核验](result-verification.md)冻结候选、实际重放审查场景；未知汇总或多种表示，按该引用的精确关系/表格检查核对。若现有程序已经从同一权威数据生成全部产物、并有等价读回检查，复用它，不重复登记。

| 任务 | 核对实际什么 | 不能由工具证明什么 |
| --- | --- | --- |
| 软件 | 真实动作、持久结果、相关恢复和入口体验 | 机械PASS不证明所有业务与环境 |
| 分析 | 原始口径、精确重算、去重与来源、未知范围 | 对平不证明归因或商业推断 |
| 经营方案 | 可执行约束、承诺、机会成本、交接一致性 | 计划不等于市场效果或已执行 |

## 最小可运行入口

脚本目录S是独立包的SKILL_DIR/scripts，或完整系统的ROOT/portable-agent-kit/scripts。

- `python3 S/challenge.py --help`：按需选择freeze/run/status/check/render；控制文件放候选工作区外。
- 审查者unittest需实际调用业务代码/计算，运行结果保存真实数量与输出；空/跳过不放行。
- 一次性关系spec只声明本次有用的关系，不列全角色或用大量文本关键词冒充语义。
- 原始失败保留；候选/输入/脚本变更使旧PASS失效。PASS只覆盖实际检查，不认证授权或独立身份。

参数和可复制的小例在result-verification.md。运行标准库脚本，不新增模型API或平台SDK；受信Python审查代码不是安全沙箱，外部行为仍遵守任务授权。不会创建定时器或停止Agent。

## 只有真正需要持久恢复时

完整本机系统仍保留原有队列和portable-agent-kit/scripts/session.py兼容入口；命令见该完整目录README/PROTOCOL。已有任务继续原门禁和锁。只有任务明确需要跨进程恢复/交接，且宿主原有记录不足时使用；不要因为有多个步骤或需要自检就初始化持久契约。独立包没有该入口，不复制不存在的脚本或临时造一套来代替。

## 评价收益

看首次业务质量、漏检、返工和宿主实际资源，分别记录执行者与共同审查开销。加载Skill、调用工具、工具自测、单次前向通过均不是普遍能力提升证据；失败归因先分清事实、理解、工具格式和环境，避免错误升级或盲目重试。
